# Decision: where collection value history lives (#111)

Status: **proposed, waiting on Ve** (2026-11-21). Unblocks #112 (snapshot writer) and #117 (chart).
#110 ("since you last looked") does not depend on this: it keeps its own one-key, device-local snapshot.

Row shape for every option: `{ day: "YYYY-MM-DD", total, priced, printings, cards, currency: "USD" }`, about 90 bytes, so ~33 KB a year.
`priced: 0` days are stored and drawn as gaps, never interpolated. No source has a USD price history, so history starts the day #112 ships (no backfill).

Caveats for A: the server only values what has synced (a mark made offline counts from its next sync), and a chart point can differ slightly from the phone's headline when the two price caches are different ages. Each point carries its own coverage, so neither reads as complete when it is not. A device with sync switched off has no history, and the chart says so.

## Recommendation

**A.** It is the only option that meets #108's success metric for someone who opens Home a few days a month. It has one writer, so no new merge rule. It reuses the hardened server-store pattern and the backup that already exists. B costs the same and gives fewer points. C cannot be backed up. D has no source.
